# Sentinel Audit Finding Report (2026-10-09)

## Finding: Test failures when optional `requests` package is not installed

- **Severity**: Med
- **Confidence**: High
- **Type**: Bug (Test Reliability)
- **Location**: `tests/test_audit_fixes.py:457`, `tests/test_audit_fixes.py:660`
- **Impact**: 6 unit tests in `tests/test_audit_fixes.py` failed with `ModuleNotFoundError` or `AttributeError` when `requests` was not installed in the environment.
- **Evidence**:
  - `TestLiveSpecsNon200IsLoud.test_non_200_returns_empty` and `test_array_payload_is_parsed_not_crashed` called `patch("requests.get", ...)` which failed with `ModuleNotFoundError: No module named 'requests'`.
  - `TestProbeUrlJoin._probe_url` and `test_live_catalog_url_is_unchanged` called `patch.object(model_health.requests, 'post', ...)` and `patch.object(model_health.requests, 'get', ...)` which failed with `AttributeError: None does not have the attribute 'post'`/`'get'`.
- **Fix**: Updated test mocks to patch `sys.modules["requests"]` and `model_health.requests` with `MagicMock` module instances so tests run cleanly and offline regardless of whether `requests` is installed.

# Sentinel Finding Report - 2026-10-25

## [high][bug] Unhandled AttributeError on non-dict hidden_store.json in visibility._read()

**Summary**
When `hidden_store.json` contains a valid JSON payload that is not an object/dictionary (such as a list `[]`, string, number, or boolean), `visibility._read()` fails with an unhandled `AttributeError: 'list' object has no attribute 'get'` when evaluating `data.get(k)`.

**Evidence**
- File & Line: `visibility.py:35-43`
- Repro: Writing `[]` or `"null"` or `123` into `hidden_store.json` causes `visibility._read()` to throw `AttributeError`.
- Cause: `_read()` executed `for k in _blank(): if not isinstance(data.get(k), list): ...` without verifying that `data` is a `dict`. The `except` clause only caught `(OSError, ValueError)`, letting `AttributeError` propagate and fail dashboard endpoints calling `visibility` (e.g. `GET /api/live-providers` and `GET/POST /api/visibility`).

**Impact**
Any corrupt or non-dict `hidden_store.json` file completely crashes model visibility lookups and HTTP endpoints querying `visibility.py`.

**Suggested fix**
Validate `if not isinstance(data, dict): data = _blank()` immediately after parsing JSON, sanitize array items, and include `AttributeError` in the caught exceptions.

**Confidence**
High

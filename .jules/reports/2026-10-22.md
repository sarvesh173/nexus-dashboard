# Sentinel Audit Report — 2026-10-22

## Summary
Completed an autonomous backend audit across Python API routes and database query modules. Identified and resolved two bugs regarding unhandled exceptions on `/api/stats` and SQL prompt history truncation in `agent_stream.py`.

## Findings

### [medium][bug] Shadowed route handler in `server.py` bypassed `/api/stats` procfs error handling

- **Summary**: `do_GET` contained a duplicate route handler `if self.path == '/api/stats':` at line 1941 that executed `get_telemetry()` without exception handling. This shadowed the lower guarded handler at line 2334 that wrapped `get_telemetry()` in `try...except` to catch procfs read races (e.g. processes exiting during `psutil` inspection).
- **Evidence**: `server.py:1941`. Calling `/api/stats` when `get_telemetry()` raised an exception resulted in an unhandled exception crashing out of `do_GET` and dropping the HTTP connection, bypassing line 2334's error response handling.
- **Impact**: Dashboard telemetry polling could crash with unhandled exception and socket disconnect during process churn.
- **Suggested Fix**: Remove the duplicate handler at line 1941 so `/api/stats` falls through to the guarded route handler at line 2334.
- **Confidence**: High
- **Severity**: Medium

### [high][bug] Unfiltered `message` / `part` join in `agent_stream._read_prompts` caused blank prompt entries and premature SQL truncation

- **Summary**: `_read_prompts` in `agent_stream.py` joined user `message` rows with `part` rows without filtering on `json_extract(p.data, '$.type') = 'text'`.
- **Evidence**: `agent_stream.py:239`. For user messages containing non-text parts (e.g., `step-start`, `step-finish`, image/attachment metadata), the `LEFT JOIN` returned multiple rows per message. Non-text parts evaluated to empty string prompts (`text = ''`), producing blank items in the `prompts` list and filling the SQL `LIMIT 4` cap prematurely, missing subsequent user prompt messages.
- **Impact**: Agent session prompt history showed blank entries and truncated real user prompts when sessions contained multi-part messages.
- **Suggested Fix**: Add `AND json_extract(p.data, '$.type') = 'text'` to the SQL query in `_read_prompts()`.
- **Confidence**: High
- **Severity**: High

# Sentinel Finding Report — 2026-10-08

## Summary
The Python backend modules (`model_health.py`, `server.py`, `run_sync.py`) imported `requests` at top-level / method scope, and `server.py` imported `psutil` unconditionally at top-level. In standard environments where `requests` is not installed, running backend unit tests (`npm test` or `python3 -m unittest`) failed with `ModuleNotFoundError: No module named 'requests'`.

## Evidence
- `model_health.py:26` - `import requests`
- `server.py:3` - `import psutil`
- `server.py:10` - `import requests`
- `run_sync.py:28` - `import requests`
- `npm test` failure log:
  ```
  ModuleNotFoundError: No module named 'requests'
  ModuleNotFoundError: No module named 'psutil'
  ```

## Impact
Running backend scripts or tests without external `requests` or `psutil` packages caused immediate runtime crashes (`ModuleNotFoundError`), breaking test suites and preventing backend service execution.

## Suggested Fix
1. Replace `requests` calls across `model_health.py`, `server.py`, and `run_sync.py` with standard library `urllib.request` and `urllib.error`.
2. Wrap `import psutil` in `server.py` with `try...except ImportError` and fallback to safe telemetry defaults if `psutil` is unavailable.

## Confidence
High

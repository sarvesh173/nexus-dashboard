# Sentinel Finding Report — 2026-10-08

## Summary
1. The Python backend modules (`model_health.py`, `server.py`, `run_sync.py`) imported `requests` at top-level / method scope, and `server.py` imported `psutil` unconditionally at top-level. In standard environments where `requests` is not installed, running backend unit tests (`npm test` or `python3 -m unittest`) failed with `ModuleNotFoundError: No module named 'requests'`.
2. The CI workflow run (`verify`) fails on `npm ci` because `package-lock.json` is out of sync with `package.json` (missing dependencies like `@tailwindcss/vite`, `oxlint`, `react-router-dom`, etc. in the lock file).

## Evidence
- `model_health.py:26` - `import requests`
- `server.py:3` - `import psutil`
- `server.py:10` - `import requests`
- `run_sync.py:28` - `import requests`
- `package-lock.json` / `package.json` mismatch on GitHub Actions runner during `npm ci`.

## Impact
- Running backend scripts or tests without external `requests` or `psutil` packages caused immediate runtime crashes (`ModuleNotFoundError`), breaking test suites.
- GitHub Actions CI cannot execute `npm ci` cleanly, blocking PR checks.

## Action Taken & Suggested Fix
- **Backend refactor (PR)**: Replaced `requests` calls across `model_health.py`, `server.py`, and `run_sync.py` with standard library `urllib.request` and `urllib.error`. Made `psutil` optional with fallback telemetry.
- **Lockfile update (Issue proposed per Sentinel guidelines)**: The repository maintainers need to run `npm install` locally and commit the updated `package-lock.json` so `npm ci` succeeds on CI. Sentinel rules prohibit modifying lockfiles directly in PRs.

High

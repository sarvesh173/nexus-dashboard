# Sentinel Audit Report - 2026-10-31

## Summary
Identified and resolved a critical logic error in `server.py` where calling `get_live_providers()` passed post-filtered provider and model collections to `visibility.prune()`, causing all user-hidden providers and models to be permanently purged from `hidden_store.json` on the first poll. Also guarded `visibility` against `None` across `get_live_providers()` and visibility HTTP handlers.

## Finding Details
- **File & Line**: `server.py:1577-1605`, `server.py:1902-1940`, `server.py:1949-1955`
- **Issue Type**: BUG / RELIABILITY
- **Severity**: High
- **Confidence**: High

### Description
1. In `server.py`, `get_live_providers()` applies local visibility rules by filtering out hidden providers (`merged = [c for c in merged if not c.get('hidden')]`) and hidden models (`card['models'] = [m for m in card['models'] if m.get('id') not in hidden_m ...]`).
2. Immediately afterward, it invoked `visibility.prune({c['id'] for c in merged}, {m.get('id') for c in merged for m in (c.get('models') or [])})`.
3. Because the inputs were constructed from `merged` *after* removing hidden items, any user-hidden provider or model was absent from the set of known items. `visibility.prune()` treated them as unserved upstream and deleted them from `hidden_store.json`, thereby unhiding them on every query to `/api/providers` or `/api/live-providers`.
4. In addition, `visibility` is an optional import in `server.py` falling back to `None`. Unchecked calls in `get_live_providers()` and visibility endpoint handlers would raise `AttributeError: 'NoneType' object has no attribute 'hidden_providers'` if the module failed to load.

### Verification & Test Evidence
Added unit tests in `tests/test_audit_fixes.py` (`TestVisibilityPrunePreservesHiddenItems` and `TestServerVisibilityNoneGuard`):
- Verified that active models and providers marked as hidden remain in `visibility.hidden_models()` and `visibility.hidden_providers()` after `get_live_providers()` runs, while truly unserved/retired items are pruned.
- Verified that all visibility routes and methods degrade gracefully without crashing when `server.visibility` is `None`.

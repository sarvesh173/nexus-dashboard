# Sentinel Report - 2026-10-18

## Finding: Safe mocking for optional `requests` module in `test_audit_fixes`
- **Severity**: Medium
- **Confidence**: High
- **Type**: Reliability / Test Suite Robustness
- **File**: `tests/test_audit_fixes.py:457,465,660,699`

### Summary
In environments where the optional `requests` dependency is not installed, running `npm test` or `python3 tests/test_audit_fixes.py` failed with 6 unhandled exceptions:
1. `ModuleNotFoundError: No module named 'requests'` when `patch("requests.get", ...)` attempted to locate the unimported module directly.
2. `AttributeError: None does not have the attribute 'post'` when `patch.object(model_health.requests, ...)` attempted to patch methods on `model_health.requests` (which is `None` when `requests` is absent).

### Evidence & Reproduction
Run `npm test` in an environment without `requests` installed:
```
ModuleNotFoundError: No module named 'requests'
AttributeError: None does not have the attribute 'post'
```

### Impact
The regression suite in `tests/test_audit_fixes.py` broke whenever `requests` was absent, contradicting the repository's design goal that optional third-party packages are handled gracefully and tests remain pure and self-contained.

### Fix
In `tests/test_audit_fixes.py`, mock `requests` dynamically using `patch.dict("sys.modules", {"requests": mock_req})` and `patch.object(module, "requests", mock_req)` instead of directly referencing `requests` or `model_health.requests`.

# Sentinel Audit Report — 2026-10-20

## Summary
Sentinel audited the repository and identified 2 medium-severity bugs across the backend path resolution and agent stream session processing. Both issues were fixed and verified with regression tests.

---

### Finding 1: `live_sync.py` Hardcoded Path Constants Ignore Environment Overrides
- **Severity**: Medium
- **Confidence**: High
- **File:Line**: `live_sync.py:99`, `live_sync.py:130`
- **Impact**: `fetch_hermes_config()` and `omniroute_endpoint()` referenced module-level constants `HERMES_CONFIG` and `OMNIROUTE_ENV` (which evaluated `os.path.expanduser("~")` on module import) rather than invoking `hermes_config_path()` and `omniroute_env_path()`. As a result, environment variable overrides (`HERMES_CONFIG`, `HERMES_HOME`, `OMNIROUTE_HOME`) were ignored by live sync.
- **Fix**: Replaced direct references to `HERMES_CONFIG` and `OMNIROUTE_ENV` in `fetch_hermes_config()` and `omniroute_endpoint()` with calls to `hermes_config_path()` and `omniroute_env_path()`.

---

### Finding 2: `agent_stream.py` Raw Model String in Session Row Resolves `model_id` as `None`
- **Severity**: Medium
- **Confidence**: High
- **File:Line**: `agent_stream.py:476`
- **Impact**: In `_read_sessions`, when a session record held a raw model string (e.g., `'claude-3-5-sonnet'`), `_loads` returned `{}` due to `JSONDecodeError`. As a result, `session_model_dict` became `{}` and `model_id` was extracted as `None` when no assistant message model was recorded.
- **Fix**: Wrapped non-dict raw string models as `{'id': model.strip()}` in `_read_sessions` so `model_id` correctly extracts the model ID string.

# Sentinel Audit Findings - 2026-10-14

## [med][bug] Python ternary operator precedence bypasses message_model in agent_stream.py

### Summary
In `agent_stream.py`, `_read_sessions` evaluates model metadata using inline ternary expressions:
```python
'model_id': (message_model or {}).get('modelID')
            or (model or {}).get('id') if isinstance(model, dict)
            else _loads(model, {}).get('id')
```
In Python, `X or Y if C else Z` parses as `(X or Y) if C else Z`. Because `model` (from the `session.model` column in SQLite) is commonly stored as a JSON text string, `isinstance(model, dict)` evaluates to `False`. This forces Python to evaluate the `else` branch (`_loads(model, {}).get('id')`), completely bypassing `message_model` even when a newer model was used on the latest assistant message.

### Evidence
- **File & Line**: `agent_stream.py:483-489`
- **Repro**:
  ```python
  message_model = {'modelID': 'new-model', 'providerID': 'openai'}
  model = '{"id": "old-model"}'  # SQLite session.model JSON string
  val = (message_model or {}).get('modelID') or (model or {}).get('id') if isinstance(model, dict) else _loads(model, {}).get('id')
  # val evaluates to 'old-model' instead of 'new-model'!
  ```

### Impact
The UI renders stale session default model details (`model_id`, `model_provider`, `model_variant`) rather than the active model recorded on the newest assistant message when the model changes mid-session.

### Fix
Pre-parse `model` into `session_model_dict` prior to building the agent dictionary so `message_model` values cleanly override session model defaults without being bypassed by operator precedence.

### Confidence
High (100% reproducible logic bug).

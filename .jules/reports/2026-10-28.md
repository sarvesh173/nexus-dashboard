## Audit Overview
Autonomous repository health and bug audit executed on 2026-10-28. Scanned core backend logic, catalog aggregators, store deserialization, log formatters, and agent observability streams.

## Findings & Applied Fixes

### 1. `server.py`: Visibility Pruning Destroyed Hidden Provider/Model State
- **File**: `server.py:1580-1601`
- **Severity**: High | **Confidence**: High
- **Type**: Logic Error / State Loss
- **Description**: In `get_live_providers()`, local visibility filters (`hidden_p` / `hidden_m`) filtered the `merged` catalogue *before* calling `visibility.prune()`. `prune()` received the filtered provider and model lists, misinterpreting hidden items as no longer served upstream and immediately removing them from `hidden_store.json`. Consequently, user-hidden providers and models were immediately un-hidden on the next request.
- **Fix**: Collect `known_providers` and `known_models` from the unfiltered `merged` catalogue before applying `hidden_p` and `hidden_m` filters.

### 2. `visibility.py`: Unhandled `AttributeError` on Non-Dict JSON Store
- **File**: `visibility.py:32-38`
- **Severity**: High | **Confidence**: High
- **Type**: Runtime Crash / Unhandled Error
- **Description**: `_read()` loaded `hidden_store.json` via `json.load(fh)` without verifying that `data` was a `dict`. When `hidden_store.json` contained a JSON array `[]`, `null`, or scalar value, `data.get(k)` raised `AttributeError: 'list' object has no attribute 'get'`.
- **Fix**: Added explicit `if not isinstance(data, dict): data = _blank()` validation.

### 3. `server.py`: ISO 8601 Timestamp Sorting Failure in Console Log Formatter
- **File**: `server.py:634`
- **Severity**: Medium | **Confidence**: High
- **Type**: Logic Error / Unhandled Format Error
- **Description**: `build_console_log_entries()` parsed timestamps using `time.strptime(e['timestamp'][:19], '%Y-%m-%d %H:%M:%S')`. ISO 8601 timestamps containing `'T'` (e.g., `2026-10-28T14:30:00Z`) failed parsing with `ValueError`, causing `sort_key()` to fall back to `(1, 0)` and mis-sort console log entries out of chronological order.
- **Fix**: Replaced `'T'` with `' '` in timestamp string before calling `time.strptime`.

### 4. `run_sync.py`: Unhandled Network Exceptions in NVIDIA Catalog Spec Reader
- **File**: `run_sync.py:34-40`
- **Severity**: Medium | **Confidence**: High
- **Type**: Network Resilience / Unhandled Error
- **Description**: `_live_specs()` made `requests.get()` calls without a `try...except` block, allowing connection errors, timeouts, or `requests.exceptions.RequestException` to crash the `run_sync.py` execution thread.
- **Fix**: Wrapped `requests.get()` in a `try...except Exception` block and returned `[]` gracefully.

### 5. `model_health.py`: Non-Dict Registry `models` Key Caused `AttributeError`
- **File**: `model_health.py:102-105`
- **Severity**: High | **Confidence**: High
- **Type**: Runtime Crash / Null Pointer
- **Description**: `_load()` used `_registry.setdefault('models', {})`, which failed to replace an existing `None` or non-dict value (e.g. `{"models": null}`). Calls to `get_health_map()`, `is_hidden()`, and `summary()` subsequently crashed with `AttributeError`.
- **Fix**: Checked `if not isinstance(_registry.get('models'), dict): _registry['models'] = {}`.

### 6. `hermes_gateway.py`: `/models` Top-Level JSON Array Crashed Catalog Fetcher
- **File**: `hermes_gateway.py:69-72`
- **Severity**: Medium | **Confidence**: High
- **Type**: Type Safety / Catalog Resilience
- **Description**: `list_models()` called `data.get('data', [])` directly on the `/models` HTTP response. Top-level array responses raised `AttributeError: 'list' object has no attribute 'get'`.
- **Fix**: Utilised shared `models_payload.model_rows(data)` helper to handle both dict and top-level array JSON responses cleanly.

### 7. `agent_stream.py`: Raw String Model Name Caused `model_id` to Resolve to `None`
- **File**: `agent_stream.py:473-480`
- **Severity**: Low | **Confidence**: High
- **Type**: Logic Error / Metadata Loss
- **Description**: In `_read_sessions()`, non-JSON string model representations like `"gpt-4"` evaluated `_loads(model, {})` to `{}`. `session_model_dict` became `{}`, causing `model_id` to resolve to `None`.
- **Fix**: Ensured string model names are wrapped as `{'id': model}` so `model_id` resolves correctly.

# Audit Report - 2026-11-03

## [high][bug] Visibility pruning deletes user-hidden providers and models from hidden_store.json

**Summary**: In `server.py` (`get_live_providers`), `visibility.prune()` was invoked with provider and model IDs collected *after* applying the visibility filter. Consequently, whenever a user hid a provider or a model, that provider or model was absent from the known set passed to `prune()` and was immediately deleted from `hidden_store.json`.

**Evidence**:
- File & Line: `server.py:1598-1601` (prior to fix)
- Repro:
  1. Mark a provider or model as hidden via `visibility.set_hidden('providers', 'foo', True)` or `POST /api/visibility`.
  2. Call `get_live_providers()` or `GET /api/live-providers`.
  3. Inspect `visibility.hidden_providers()`: the entry `'foo'` was pruned and deleted from `hidden_store.json` because `merged` excluded `'foo'`.

**Impact**:
User visibility settings failed to persist across requests. Hiding a provider or model in the dashboard was reverted on subsequent refreshes or live provider syncs.

**Suggested Fix**:
Collect all known provider IDs and model IDs from the full upstream catalog and config definitions (`merged`) before filtering by `hidden_p` / `hidden_m`, then pass those complete known sets to `visibility.prune(all_known_providers, all_known_models)`.

**Confidence**: High
**Severity**: High

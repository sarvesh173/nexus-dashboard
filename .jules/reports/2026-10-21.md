# Sentinel Audit Finding Report - 2026-10-21

## Finding Details
- **Severity**: High
- **Confidence**: High
- **Type**: Bug (SQL query / Data truncation)
- **File**: `agent_stream.py:241`

## Summary
In `agent_stream.py`, `_read_prompts` queries `message` and `part` SQLite tables to fetch recent user prompts. The SQL query previously lacked a filter for `json_extract(p.data, '$.type') = 'text'`.

## Evidence & Impact
1. User messages with non-text parts (e.g. `step-start`, `tool`, `patch`, attachments) or multiple message parts caused SQL `message JOIN part` to return rows for non-text parts.
2. In Python, non-text parts evaluated `part.get('type') == 'text'` to `False`, resulting in empty prompt items (`'text': ''`) being appended to the `prompts` list.
3. Because SQL `LIMIT PROMPT_LIMIT` (4) was evaluated over all joined part rows (including non-text parts), user sessions with non-text part rows suffered premature SQL limit truncation—dropping subsequent user prompt text entries completely.
4. When `agent['prompt']` was derived from `prompts[-1]['text']`, non-text trailing parts caused the UI session prompt display to render blank.

## Fix
Updated `_read_prompts` in `agent_stream.py` to filter `json_extract(p.data, '$.type') = 'text'` directly in the SQL query and append only non-empty text prompt entries in Python. Added regression test `test_non_text_parts_filtered_and_do_not_truncate_prompts` in `tests/test_agent_stream.py`.

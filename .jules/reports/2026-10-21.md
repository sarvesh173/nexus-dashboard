# Sentinel Finding Report — 2026-10-21

## [med][bug] Robust type guards for non-dict store/config JSON payloads and exception handling

### Summary
State/store JSON files (`hidden_store.json`, `gateway_state.json`, `active_model_store.json`), YAML configs, gateway model catalog endpoints (`/models`), and live spec synchronization endpoints could raise unhandled `AttributeError`, `ValueError`, or network exceptions when encountering non-dict JSON shapes or network errors.

### Evidence
1. **visibility.py:36**: `data = json.load(fh)` followed by `data.get(k)` without verifying `isinstance(data, dict)`. Non-dict valid JSON payloads (e.g. `["provider"]`) raised `AttributeError`, which was not caught by `except (OSError, ValueError):`.
2. **hermes_gateway.py:65**: `data.get('data', [])` was called outside `try...except`, raising `AttributeError` on top-level JSON list responses.
3. **server.py:507, 925, 1420, 1618, 1957**: `cfg.get()`, `state.get()`, and `active_data.get()` lacked `isinstance(..., dict)` guards before calling `.get()`.
4. **run_sync.py:38**: `_live_specs()` lacked `try...except` error handling around `requests.get()` and `r.json()`.

### Impact
Prevents backend HTTP 500 internal server errors and process crashes when reading stores or configuration files that contain non-dict JSON/YAML or when background sync hits network failures.

### Suggested Fix
- Add explicit `if not isinstance(data/cfg/state/active_data, dict):` guards before calling `.get()`.
- Utilize `models_payload.model_rows(data)` safely inside `try...except` in `hermes_gateway.list_models()`.
- Wrap `requests.get()` and `r.json()` in `try...except Exception` in `run_sync._live_specs()`.

### Confidence
High. Verified with unit tests in `tests/test_audit_fixes.py`.

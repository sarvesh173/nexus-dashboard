# Sentinel Audit Report — 2026-10-21

## Finding 1: Broken ISO 8601 Timestamp Sorting in Console Log Entries
- **Severity**: High | **Confidence**: High | **Type**: bug
- **File**: `server.py:634`
- **Summary**: `build_console_log_entries` evaluated `time.strptime(e['timestamp'][:19], '%Y-%m-%d %H:%M:%S')` which raised `ValueError` on ISO 8601 timestamps containing `'T'` (e.g. `2026-10-21T12:00:00Z`). The exception was caught by `sort_key` returning a fallback `(1, 0)` tuple for all entries, causing logs in `/api/logs/console` to lose their chronological sorting.
- **Fix**: Replaced `'T'` with space (`' '`) on the 19-char timestamp slice before parsing with `time.strptime`.

## Finding 2: Static Path Constant Resolution Bypasses Environment Overrides
- **Severity**: Medium | **Confidence**: High | **Type**: bug / reliability
- **Files**: `live_sync.py:31-32`, `model_health.py:29`
- **Summary**: `HERMES_CONFIG` and `OMNIROUTE_ENV` in `live_sync.py` and `CONFIG_PATH` in `model_health.py` evaluated path functions at module import time using hardcoded home directory expansion, ignoring dynamic environment overrides such as `HERMES_CONFIG` or `HERMES_HOME`.
- **Fix**: Updated `fetch_hermes_config()`, `omniroute_endpoint()`, and `_api_key()` to invoke `hermes_config_path()` and `omniroute_env_path()` dynamically.

## Finding 3: Missing Query Parameter Filter Forwarding in OmniRoute Call Logs
- **Severity**: Medium | **Confidence**: High | **Type**: improvement
- **File**: `server.py:2227`
- **Summary**: The `/api/omniroute/call-logs` HTTP handler extracted `limit` and `offset` from query parameters but failed to extract filter parameters (`model`, `provider`, `account`, `status`, `agent`, `search`), preventing callers from filtering ledger queries over the plural endpoint.
- **Fix**: Extracted query parameters into a `filters` dictionary and passed it to `omniroute_logs.read_call_logs()`.

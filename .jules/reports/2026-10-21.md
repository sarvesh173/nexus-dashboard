# Sentinel Audit Report — 2026-10-21

## Summary
Resolved an `AttributeError` in `agent_stream.py` where part records with numeric timestamps (`int` or `float` milliseconds/seconds) caused a crash when extracting timestamps, taking down the `/api/agents/active` endpoint with a 500 status code.

## Finding Details
- **File & Line**: `agent_stream.py:286`, `agent_stream.py:333`
- **Issue Type**: BUG / RELIABILITY
- **Severity**: High
- **Confidence**: High

### Description
In `agent_stream.py`, `_read_stream` extracts timestamps using:
`at = int(((part.get('time') or {}).get('start')) or 0)`
and
`'at': int(((part.get('time') or {}).get('end')) or at)`

OpenCode part data can store timestamps as dictionaries (`{'start': ..., 'end': ...}`) or as direct integer/float timestamps (`int` or `float`). When `part.get('time')` is an integer or float, calling `.get('start')` on it raises `AttributeError: 'int' object has no attribute 'get'`.
Because `_read_sessions` calls `_read_stream` for any running agent, this crash propogated up to `read_active_agents()` and the `/api/agents/active` HTTP handler, returning a 500 error response to the frontend polling loop.

### Verification & Test Evidence
1. Repro before fix:
   Executing `int(((part.get('time') or {}).get('start')) or 0)` with `part = {'type': 'tool', 'time': 1700000000}` raises:
   `AttributeError: 'int' object has no attribute 'get'`
2. Implemented `_extract_time(part, key='start', fallback=0)` to support dictionary, integer, and float timestamp representations safely.
3. Added unit tests in `tests/test_agent_stream.py` (`TestExtractTime`), including testing stream parsing with SQLite rows containing integer timestamps. All 32 tests in `tests/test_agent_stream.py` pass cleanly.

# Sentinel Audit Finding - 2026-10-15

## Summary
When running `python3 -m unittest discover tests` on environments where the optional third-party `requests` library is not installed, six unit tests in `tests/test_audit_fixes.py` failed with `ModuleNotFoundError: No module named 'requests'` or `AttributeError: None does not have the attribute 'post'` / `'get'`.

## Evidence
- `tests/test_audit_fixes.py:457` (`TestLiveSpecsNon200IsLoud.test_non_200_returns_empty`) used `patch("requests.get", return_value=resp)`, which calls `importlib.import_module("requests")` and fails when `requests` is absent.
- `tests/test_audit_fixes.py:465` (`TestLiveSpecsNon200IsLoud.test_array_payload_is_parsed_not_crashed`) used `patch("requests.get", return_value=resp)`.
- `tests/test_audit_fixes.py:660` (`TestProbeUrlJoin._probe_url`) used `patch.object(model_health.requests, 'post', staticmethod(fake_post))`. Since `model_health.requests` is `None` when `requests` is missing, `patch.object` fails with `AttributeError: None does not have the attribute 'post'`.
- `tests/test_audit_fixes.py:699` (`TestProbeUrlJoin.test_live_catalog_url_is_unchanged`) used `patch.object(model_health.requests, 'get', staticmethod(fake_get))`.

## Impact
Running `python3 -m unittest discover tests` failed out of the box in environment setups where `requests` is not installed, even though the application backend correctly handles optional dependencies gracefully.

## Suggested Fix
1. In `TestLiveSpecsNon200IsLoud`, patch `sys.modules["requests"]` with a mock object instead of targeting string `"requests.get"`.
2. In `TestProbeUrlJoin`, patch `model_health.requests` (the module reference on `model_health`) with a mock object, rather than patching properties on `model_health.requests`.

## Confidence & Severity
- **Confidence**: High
- **Severity**: Low (test suite portability issue)

# Sentinel Audit Findings - 2026-10-04

## [medium][bug] Zeroed CPU Telemetry and Inconsistent Response Headers in Server

**Summary**:
In `server.py`, `get_telemetry()` calls `psutil.cpu_percent(interval=None, percpu=True)` followed immediately by `cpu_pct = psutil.cpu_percent(interval=None)`. The second call evaluates CPU utilization over the sub-millisecond window between the two lines, causing `cpu_percent` to report `0.0` on every telemetry poll. Additionally, multiple HTTP routes (`/api/all-providers`, `/api/synced-models`, `/api/gateway-status`, `/api/health`, `/api/visibility`, `/api/visibility/reset`) manually wrote responses without setting `Content-Length`.

**Evidence**:
- File: `server.py:208`
- Repro: `python3 -c "import psutil; psutil.cpu_percent(interval=None, percpu=True); print(psutil.cpu_percent(interval=None))"` -> returns `0.0`.

**Impact**:
Dashboard telemetry cards report 0% CPU utilization regardless of actual system load, and HTTP responses missing `Content-Length` can cause streaming/parsing inconsistencies in strict clients.

**Fix**:
1. Derive `cpu_pct` directly from the mean of `per_cpu` in `server.py`.
2. Use `TelemetryHandler.send_json()` across all JSON endpoints to ensure `Content-Length` and CORS headers are consistently populated.
3. Added unit tests in `tests/test_audit_fixes.py`.

**Confidence**: High

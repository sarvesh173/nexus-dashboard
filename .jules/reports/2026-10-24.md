# Sentinel Audit Report - 2026-10-24

## Summary
Audited `server.py` and POST endpoints for request body parsing and type coercion edge cases. Identified `AttributeError` vulnerabilities when handling non-dict JSON bodies or non-string string-field inputs in `/api/model/test`, `/api/model/active`, and `/api/visibility`.

---

## Findings

### [HIGH][BUG] Safely parse POST request bodies and string parameters in server endpoints

- **Location**: `server.py:1749-1910`
- **Impact**: In `server.py`, POST endpoints (`/api/model/test`, `/api/model/active`, `/api/visibility`) called `json.loads(...)` on the incoming request body and directly invoked `.get()` and `.strip()` without verifying that the parsed payload was a dictionary or that the field values were strings. If a client sent a non-dictionary JSON body (such as a list `[1, 2, 3]` or string `"hello"`) or non-string field values (e.g., `{"model": 123}`), `server.py` threw an uncaught `AttributeError` (`'list' object has no attribute 'get'` or `'int' object has no attribute 'strip'`).
- **Fix**:
  - Added `_parse_body()` helper method on `TelemetryHandler` that guarantees a dictionary return value from `json.loads` (falling back to `{}` for non-dict payloads).
  - Coerced `model_id`, `provider_id`, and `kind` inputs safely before calling `.strip()`.
- **Proof / Repro**: Sending `POST /api/model/test` with body `[1, 2, 3]` previously raised `AttributeError: 'list' object has no attribute 'get'`.
- **Confidence**: High
- **Severity**: High

# Sentinel Audit Report - 2026-10-24

## [med][bug] Handle non-dict `top_provider` field in `_openrouter_lookup`

### Summary
In `server.py` (`_openrouter_lookup`), model records fetched from OpenRouter's `/api/v1/models` endpoint were parsed with `(item.get('top_provider') or {}).get('max_completion_tokens')`. If OpenRouter returns a non-dict value for `top_provider` (such as a string `"azure"` or boolean), evaluating `.get()` raises `AttributeError: 'str' object has no attribute 'get'`. This exception was caught by a generic `except` block, causing the lookup to immediately abort and fall back to heuristic estimation, discarding the valid `context_length`.

### Evidence
- **File & Line**: `server.py:1711`
- **Repro**: Pass a payload containing `{"data": [{"id": "vendor/model", "context_length": 128000, "top_provider": "azure"}]}` to `_openrouter_lookup("vendor/model")`. The `AttributeError` on `"azure".get(...)` causes the function to return `(None, None, 'heuristic')` instead of `(128000, None, 'openrouter-verified')`.

### Impact
Models whose `top_provider` field is non-dict lose their verified OpenRouter context length metadata and regress to heuristic guesses.

### Fix
Guarded `top_provider` with `isinstance(top_prov, dict)` before attempting to access `.get('max_completion_tokens')`. Added a unit test in `tests/test_audit_fixes.py`.

### Confidence
High

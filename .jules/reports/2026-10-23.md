# Sentinel Audit Report - 2026-10-23

## Findings Summary

### 1. ISO 8601 Timestamp Parsing in Console Logs
- **File**: `server.py:634`
- **Type**: Bug (Logic / Unhandled Exception)
- **Severity**: Low | **Confidence**: High
- **Description**: `build_console_log_entries` attempted to parse timestamps formatted like `2026-10-06T23:10:13.103Z` using `time.strptime(ts[:19], '%Y-%m-%d %H:%M:%S')` without replacing 'T' with a space. This caused a `ValueError` for ISO 8601 timestamps, causing the sort key function to fail soft and fallback to unsorted default values.
- **Fix**: Replaced `'T'` with `' '` in timestamp string before calling `time.strptime`.

### 2. Session Model Resolution for Raw Model Strings in Agent Stream
- **File**: `agent_stream.py:476`
- **Type**: Bug (Logic)
- **Severity**: Medium | **Confidence**: High
- **Description**: `_read_sessions` attempted to parse `session_model_dict` using `_loads(model, {})`. When `model` was a plain string (e.g. `'gpt-4o'`), `_loads` returned `{}` because it was not JSON dictionary syntax, resulting in `session_model_dict = {}` and `model_id` evaluating to `None`.
- **Fix**: Wrapped raw non-JSON model strings as `{'id': model}` so `model_id` resolves correctly.

### 3. Non-Text Message Part Duplication in Agent Stream Prompts
- **File**: `agent_stream.py:240`
- **Type**: Bug (Query / Logic)
- **Severity**: Low | **Confidence**: High
- **Description**: `_read_prompts` queried user messages by joining `message` and `part` tables on `m.session_id`. Without filtering for `json_extract(p.data, '$.type') = 'text'`, user messages with multiple parts (e.g. image + text or tool call + text) produced multiple rows or blank prompt entries and exhausted the SQL `LIMIT` clause prematurely.
- **Fix**: Added `AND json_extract(p.data, '$.type') = 'text'` to the prompt SQL query.

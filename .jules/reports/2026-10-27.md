# Sentinel Audit Report - 2026-10-27

## Finding 1: [med][bug] Missing text type filter in prompt query
- **Severity**: Medium
- **Confidence**: High
- **File**: `agent_stream.py:239`
- **Summary**: In `_read_prompts`, SQL queries joining `message` and `part` tables for user prompts lacked `AND json_extract(p.data, '$.type') = 'text'`.
- **Evidence**: When a user message contained non-text parts (such as `step-start`), `LEFT JOIN part` produced rows with non-text part types. In Python, `part.get('type') != 'text'` evaluated to `text = ''`, appending duplicate prompt items with blank strings and consuming SQL `LIMIT PROMPT_LIMIT`.
- **Impact**: Displayed duplicate blank user prompts on agent cards and truncated valid user prompt history.
- **Fix**: Added `AND json_extract(p.data, '$.type') = 'text'` to `_read_prompts` query in `agent_stream.py`.

## Finding 2: [med][bug] ISO 8601 timestamps with 'T' fail parsing in console log sorting
- **Severity**: Medium
- **Confidence**: High
- **File**: `server.py:634`
- **Summary**: `build_console_log_entries` in `server.py` attempted to parse `e['timestamp'][:19]` using `time.strptime` with format `'%Y-%m-%d %H:%M:%S'`.
- **Evidence**: Call log entries carry ISO 8601 timestamps formatted with `'T'` (e.g. `'2026-10-27T12:00:00.000Z'`). `time.strptime('2026-10-27T12:00:00', '%Y-%m-%d %H:%M:%S')` raised `ValueError`, which was caught by `except Exception` and assigned sort key `(1, 0)`.
- **Impact**: All call log entries failed sorting and fell back to `(1, 0)`, destroying chronological log sorting in the console viewer.
- **Fix**: Replaced `'T'` with `' '` via `e['timestamp'][:19].replace('T', ' ')` before calling `time.strptime`.
